# BriefOps Relay — Video Production Plan

## Creative direction

Make a 2:45–2:55 English product presentation. A **synthetic adult Korean woman
presenter** introduces the problem and transitions between real product scenes.
She is a fictional host, not a real person or a lookalike. Her role is
professional, warm, and credible: clean navy blazer, minimal jewelry, neutral
studio makeup, modern presentation stage, and calm confident delivery.

Generated presenter shots are atmosphere and narration support. Every terminal,
dashboard, Contract, Audit, and score shown in the video must come from a real
BriefOps Relay run or the committed offline demo.

## Storyboard (target: 2:52)

| Time | Visual | Spoken message |
| --- | --- | --- |
| 0:00–0:16 | Presenter beside a slide: “Codex can code. Projects still lose context.” | Long-running work fails when requirements, decisions, and code become disconnected. |
| 0:16–0:30 | Real terminal: `briefops relay doctor`; title card. | BriefOps Relay is an evidence-backed execution layer for Codex projects. |
| 0:30–0:58 | Real `prepare` output and Contract report. | It turns bounded repository evidence into a task-scoped execution contract. Every item cites a real evidence ID. |
| 0:58–1:20 | Report evidence detail and contract cards. | Relay rejects invented citations instead of trusting file names or line numbers generated by a model. |
| 1:20–1:52 | Seeded incomplete diff, then real Audit results. | After Codex changes code, Relay audits each contract item against the Git diff and reports met, at-risk, violated, or unverified. |
| 1:52–2:12 | Presenter beside a large “63 / FAIL” example, then remediation prompt. | The score is deterministic: the model explains a verdict, but code computes the completion gate. |
| 2:12–2:32 | Real Handoff and Report. | The next Codex session receives a verified handoff: what changed, what was checked, and what remains risky. |
| 2:32–2:46 | Architecture slide: evidence → Contract → Audit → Handoff. | The live path is opt-in through authenticated Codex; the offline demo is reproducible without credentials. |
| 2:46–2:52 | Presenter closing slide. | Codex remembers a task. BriefOps Relay preserves the project. |

## Capture order

1. Run the deterministic offline demo and capture the report at 1440×900.
2. Capture `relay doctor`, `prepare --dry-run`, `audit --collect-diff`, handoff, and report in a clean terminal profile.
3. Capture the local live report only after redacting repository-specific paths and ensuring no secret is visible.
4. Generate presenter shots after the script timing is locked.
5. Assemble presenter + real capture scenes; do not use generated terminal or dashboard imagery.

## Editorial rules

- No background music unless its license is documented; silence is preferable.
- Burn in English captions; keep critical UI labels visible for at least 2.5 seconds.
- Use 16:9, 1920×1080, H.264 video and AAC audio.
- Do not include keys, absolute local paths, private source code, browser tabs, or notifications.
- State that the presenter is synthetic only if a platform or submission rule requires disclosure.
